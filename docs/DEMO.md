# Operation demo and large-PDF stress test

[Back to the project home](../README.md) · [Download for Windows](https://github.com/CBH2028/pdf-size-reducer/releases/latest)

## Full operation video

[![PDF Size Reducer operation demo](media/operation-demo.gif)](https://github.com/CBH2028/pdf-size-reducer/releases/download/v3.2.0/PDF_Size_Reducer_Operation_Demo.mp4)

The video was captured from the real v3.2.0 interface and shows the complete workflow:

1. scan a synthetic 97.92 MiB, 48-page PDF in the background;
2. browse full-view thumbnails and estimated storage for 48 complete Figures;
3. open an approximately 240 DPI preview and zoom in to inspect thin lines;
4. exclude Figures that must remain unchanged and enter an exact target size;
5. run the task and confirm that the output file was generated.

[Download the HD MP4 (1440 × 900, 26 seconds)](https://github.com/CBH2028/pdf-size-reducer/releases/download/v3.2.0/PDF_Size_Reducer_Operation_Demo.mp4)

## Demo PDF

[Download `PDF_Size_Reducer_Stress_Demo_97.92MB.pdf`](https://github.com/CBH2028/pdf-size-reducer/releases/download/v3.2.0/PDF_Size_Reducer_Stress_Demo_97.92MB.pdf)

## Measured performance

In the recorded test environment, scanning took about 6.89 seconds and scanning plus every thumbnail took about 9.24 seconds. The largest Qt event-loop pause was about 125.81 ms, and peak memory for the main process was about 189.55 MiB. The interface remained responsive and the scan could be stopped safely.

Hardware, storage speed, and PDF structure affect real results. These measurements are intended for regression comparison rather than as fixed performance guarantees.

## Reproduce the test

Run the generated-file stress test:

```powershell
.\.venv\Scripts\python.exe .\tools\stress_test.py `
    --pages 48 --image-width 1600 --image-height 1000 `
    --vector-paths 90 --timeout 300
```

Run the same UI responsiveness test with an existing PDF:

```powershell
.\.venv\Scripts\python.exe .\tools\stress_test.py `
    --pdf "D:\path\large.pdf" --timeout 300
```

`tools/record_demo.py` captures frames from Qt widgets instead of the desktop, so notifications, other windows, and personal desktop content cannot appear in the recording.
