# v3.13.1 - Fix page drag-and-drop

Fix a regression in the simple PDF composer where pages could be dragged but releasing them did not insert or reorder pages.

## What changed

- Enable drag-and-drop reception on the actual page display areas, not just the surrounding lists.
- Restore material-to-result page insertion, result-page reordering and PDF file drops into the material pane.
- Keep the simple two-pane interface and all existing source-file protections. No changes to the compression accelerator.

## Also included since the last public release, v3.10.0

- **A simpler default composer:** result pages on the left, material pages on the right. Load multiple PDFs, drag selected pages into position, reorder them visually, then save. Only Add PDF, Save PDF and Advanced composition remain visible as buttons.
- **Advanced tools when needed:** the composition tree, nested groups/bookmarks, page ranges, extra insertion controls and whole-document merge live under Advanced composition. Switching modes preserves the plan and undo history.
- **Merge and compress:** assemble original PDF pages without rasterizing them, then optionally continue in the existing accelerated compression workspace. Save cancellation and declined overwrites keep the arrangement intact.
- **A focused feature set:** remove the former PDF text editor, automatic text-region editing and text-insertion tools. Page insertion and omission affect only a new-document composition plan, never the source PDF.
- **Responsive previews and safer output:** on-demand thumbnails, zoom previews, cancellable isolated jobs, source-state checks and protection against overwriting loaded documents. Whole-file merge also retains its sortable, undoable queue.

See the [composition guide](https://github.com/CBH2028/pdf-size-reducer/blob/v3.13.1/docs/COMPOSING.md) for controls, resource limits and document-preservation caveats. The existing Rust/C++ accelerator is unchanged; this release does not claim a new compression speedup.

## Regression coverage

Drag tests now send events through Qt's viewport event dispatch instead of directly calling the drop handler. New coverage includes mouse press and drag initiation, single- and multi-page insertion/reordering, leaving the drop area, switching modes, resizing and rejecting unsupported drops. The OS drag loop is replaced in automated mouse-chain unit tests; the viewport and application handlers are not bypassed.

The strengthened tests reproduce eight failures against the previous implementation. The packaged simple-composer check now validates viewport event delivery, insertion, reordering, undo and original-page export.

All **216 Python regression tests passed**. The Windows-platform diagnostic also confirmed that the unmodified application now receives drag-enter, drag-move and drop events through the viewport and inserts the page.

The packaged executable passed all five checks (exit code 0): native-worker discovery, whole-merge UI, advanced composer, viewport-dispatched simple composer and the existing compression workflow.

Run the updated **v3.13.1** executable to use the fix. Already-open v3.13.0 windows do not update automatically.
